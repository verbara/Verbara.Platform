## Context

R5.1 "Production Readiness + Ops Toolkit" shipped 2026-04-23 across 3 repos. The handoff captured **13 known limitations** (canonical source: `docs/plans/completed/2026-04-22-r5.1-implementation-plan.md` §1279-1313 + `CHANGELOG.md` §1.10.0 Known limitations) plus **R5.2 carry-forward tickets** that turned out to be *two separate sets* conflated in memory: (a) **5 new R5.2 features** defined in the release train spec, and (b) **7 carry-forward tickets** rolled up from the limitations themselves. R5.2 actual baseline is therefore 5+7=12 items minimum, before any new candidates surface.

A deep audit (docs + code, 4 repos) post-ship revealed: **8 concrete pendings not captured** in the official handoff, **7 productization categories** outside any current roadmap, **2 in-source TODOs**, and **3 limitations mis-categorized** (one needs upgrade, one removal, one explicit blocker tag). One unmerged feature branch (`feat/calling-permissions`, 14 commits SDK, 14↔298 div from main) needs an explicit decision gate per the release train spec.

This document is the **single source of truth** for what R5.2 brainstorm (target start ~2026-05-07) inherits. It does not write the spec — it bounds it.

## Forced decisions (4 points)

### D-FORCE-1 · COS branch resolution
**State:** `feat/calling-permissions` SDK branch — 14 commits ahead, 298 behind `main`. Orphaned since marzo 2026. Release train §344-356 already defines gates.

**Options:**
- **(a) Merge to R1.5 SDK** as `Asterisk.Sdk.CallingPermissions` opt-in package (no Platform UI consumer yet) — closes branch debt, customer can opt-in.
- **(b) Defer with explicit ADR** "COS deferred indefinitely; rebase against vN if customer-driven" — closes ambiguity without code merge.
- **(c) Merge to R5.2** with UI add-on — only if a customer enterprise deal triggers gate per spec §352.

**Recommendation:** **(b)** — author `decisions/0008-cos-deferred-customer-driven.md` ADR before R5.2 brainstorm. Branch rebase cost grows weekly; locking a decision stops the bleed. (a) is appealing but introduces a new SDK package without customer signal — violates principle "0 breaking changes in minors + only ship what has demand". (c) waits for demand we don't see today.

### D-FORCE-2 · Productization gaps roll-up (Table 5)
**State:** 7 categories outside any roadmap. Each is 1-3 weeks of work. Total: 6-12 weeks across all of them.

**Options:**
- **(a) Add explicit "Production Validation" sub-track to R5.3** — load tests + SLOs + pen-test + Getting Started + OpenAPI. Expands R5.3 from 1.5-2 weeks → 4-5 weeks.
- **(b) Split R5.3 → R5.3 (Admin Completeness) + R5.4 (Production Validation)** — keeps R5.3 fast (1.5-2 sem), adds new R5.4 sub-release.
- **(c) Accept that R5 train ships without production-validation track** — defer all 7 categories to v1.11 / 2.0.

**Recommendation:** **(b) Split into R5.3 + R5.4.** R5.3 keeps its current scope discipline (admin completeness + R4 closure); R5.4 lands ~3-4 sem later with the production-validation deliverables that enterprise procurement will ask for. (c) means R5 ships "feature-complete but production-unfit" — incompatible with the user's "no shortcuts" directive. (a) inflates R5.3 past its 2-sem cadence and risks the QA gap before R5.4/v1.11 features.

### D-FORCE-3 · Limitation list hygiene
- **F.1:** Limitation #1 → R5.2 execution item, not follow-up. Add to brainstorm input as P0.
- **F.2:** Limitation #8 (Task K NO-OP) → remove from "13 known limitations". Keep as plan-completed footnote only.
- **F.3:** Limitation #10 (AOT warnings) → mark explicit-blocker for v2.0-stable. Add to v2 roadmap entry.

**Recommendation:** Apply all three as immediate doc edits when next CHANGELOG / memory entry is touched. No code impact.

### D-FORCE-4 · R1.5 SDK VoiceAi Refresh during QA gap
**State:** Branch `r1.5-voiceai-refresh` per memory not yet created in SDK; release train §325-340 defines scope (ElevenLabs Flash 2.5, Deepgram Aura 2, Whisper V3 local).

**Options:**
- **(a) Execute R1.5 in QA gap** (background subagent, ~1 sem) — uses idle time productively, ships SDK 1.15.1 separate from R5 cadence.
- **(b) Skip / defer R1.5** — focus QA gap purely on R5.1 baking + R5.2 spec writing.

**Recommendation:** **(a) Execute R1.5.** Aditivo, zero deps with R5, can fit one subagent worker without distracting from R5.2 spec authoring. New providers materially improve AgentAssist competitiveness (Flash 2.5 < 150ms TTFA matters for live demos). Skipping wastes the 2-week window.
