# Plan — Typification P2c.1: per-tenant LLM config (BYO-only)

## Context
Today the LLM provider is a **single global config** (`AddPlatformLlm` binds one `LlmProviderOptions` via `IOptions<>`, a singleton shared by every tenant). For a multi-tenant product that's wrong: one shared key, no per-tenant isolation/cost-control, no BYO, no residency. **P2c.1** makes the provider **per-tenant, bring-your-own** — each tenant configures its own provider + encrypted credentials, with a pluggable multi-provider abstraction (OpenAI-compatible / Azure OpenAI / Anthropic), resolved per-tenant at call time, fail-closed.

Approved spec: `Verbara.Platform/docs/specs/2026-06-21-typification-p2c-per-tenant-llm-config.md`. **Out of scope → P2c.2:** platform-managed LLM as a metered/gated/billed service, data-residency/no-train enforcement, per-tenant resilience isolation. **Load-bearing principle:** AI is strictly opt-in — deterministic typification (P0 cascading forms + P1 prefill) is the floor and never needs an LLM; "no provider configured" is a **valid, non-error** mode (agent-driven typification). Cross-repo: **Platform** (e.g. 2.14.0) + **Web** (e.g. 3.10.0-web), released independently. No Pro change.

## Two resolved decisions
1. **Classifier refactor:** inject `ILlmProviderResolver` into `DefaultTypificationAiClassifier` (replacing `ILlmProvider`+`IOptions`), add `EntityId tenantId` to `ClassifyAsync`, resolve internally; `null` resolve → return `null` (the §0 fail-closed seam — `ConversationEndpoints.cs:306` already maps `null`→`EmptySuggestion`). Keeps all degrade-to-null logic in one place; model-id-for-provenance comes from the resolved config. Tenant id is already at the call site (`ConversationEndpoints.cs:242`).
2. **Permission:** API enforces `typification:ai:configure` (already seeded `PermissionSeeder.cs:194`, granted Manager/System-Admin, emitted in the JWT `permissions` claim). Web page-guard + sidebar use the same string. Fallback if QA finds a locked-out admin: `requiresAny={['typification:ai:configure','system:typification:configure']}`.

## Two spec corrections found during exploration
- `tenant_id` column is **TEXT** (not uuid) — every Platform table uses TEXT ids via `EntityId.From(GetString(...))`.
- `ILlmProvider` is a **dual-consumer seam**: Flows `ai_classify`/`ai_generate` AND the typification classifier both resolve the global `ILlmProvider`. The `AddPlatformLlm` reshape must **keep** the global registration (Flows) and only **add** the resolver + named clients.
