# Plan — Platform v1.9.0 "Secure + Current" (R3)

**Fecha:** 2026-04-20 · **Target:** v1.9.0 · **Tipo:** Minor bump + P0 security + foundation adoption
**Depende de:** SDK v1.15.0 + Pro v1.10.0-pro (shipped 2026-04-20) · **Sigue:** R1 Pre-v2 Foundation
**Track:** A (Pre-v2 continuation) · **Estimación:** 1-2 semanas · **Repos:** `Asterisk.Platform`

---

## Context

Track A post-R1 reordenado a `R3 → R4 → R2` con `R1.5` en rama paralela. Este plan ejecuta **R3** en Platform.

**Estado actual Platform (2026-04-20):**
- Version `1.8.1` (`Directory.Build.props` línea 28)
- SDK pin `1.11.1` (`Directory.Packages.props`: Hosting + Push) — **4 minors detrás** (SDK es 1.15.0)
- Pro pin `1.8.1-pro` (21 refs `Pro.*`) — **2 minors detrás** (Pro es 1.10.0-pro)
- 1 file consume `Asterisk.Sdk.Pro.Resilience` (`Program.cs`) — paquete eliminado en Pro 1.9.0-pro via ADR-0029, **bloquea restore**

**Por qué este release ahora (no esperar R2 preview):**
1. **P0 security pendientes:** impersonation privilege escalation + MFA policy bypass (server-side) — vulnerabilidades conocidas, no aceptan espera
2. **Debt acumulado:** 4 minors SDK / 2 minors Pro detrás genera restore-breaks y tests rot a medida que Pro/SDK siguen avanzando
3. **R3 se mantiene en stable (SDK 1.15 + Pro 1.10), NO preview** — desacopla de R2 preview1 bake time

**Decisión de partición: v1.9.0 (este plan) + v1.9.1 paralelo a R4:**
Auditoría profunda (2026-04-20) detectó que "adopt `Asterisk.Sdk.Resilience`" tiene scope mayor de lo que sugiere el rename namespace: Platform tiene 26 HttpClients externos, 2 retry loops hand-rolled, 16 BackgroundServices, custom `CircuitBreakerPolicy` casera para webhooks, 3 HealthChecks sin circuit awareness, S3MediaStorage sin wrap. Wrap comprehensivo = 4-6 sprints. Partición:
- **v1.9.0 (este plan)** = bump + foundation adoption + **Resilience MVP en 3 critical call-sites** (webhooks, SMTP, OIDC) + P0 security + Sub-A fixes
- **v1.9.1 "Resilience Coverage"** (plan separado, paralelo a R4) = 9 channel connectors + 16 BackgroundServices + 3 HealthChecks + S3

Esta partición **no es un shortcut**: P0 security no debe esperar coverage horizontal, y v1.9.1 puede shipear en paralelo a R4 porque no cambia API surface.

## Alcance

### A. Package bump + foundation adoption (~30% LOC, mecánico)

- `Directory.Packages.props` — SDK 1.11.1 → **1.15.0** (2 refs: `Asterisk.Sdk.Hosting`, `Asterisk.Sdk.Push`) y Pro 1.8.1-pro → **1.10.0-pro** (21 refs `Asterisk.Sdk.Pro.*`)
- Eliminar `Asterisk.Sdk.Pro.Resilience` reference (paquete desapareció en Pro 1.9.0-pro)
- `src/Asterisk.Platform.Api/Program.cs` — reemplazar `using Asterisk.Sdk.Pro.Resilience.DependencyInjection;` por `using Asterisk.Sdk.Resilience.DependencyInjection;` + `services.AddAsteriskResilience();`
- Adoptar `Asterisk.Sdk.Cluster.Primitives` donde corresponda (consumers de `Pro.Cluster.ClusterEvent` — confirmar durante kickoff si Platform consume directamente)
- Adoptar `AsteriskSemanticConventions.{Tenant,Event,Node}` — auditar call-sites manuales `SetTag("tenant.id", ...)` / `SetTag("event.*", ...)` / `SetTag("node.*", ...)` y reemplazar por constantes tipadas

**Acceptance:** `dotnet restore` limpio sin referencias a `Pro.Resilience`; grep manual `"tenant.id"` post-migración = 0 call-sites en strings literales.

### B. T27 event bridges enrollment

Opt-in DI wiring en `Program.cs`:
```csharp
services
    .WithClusterEventBridge()                                   // cluster.node.*.state.changed
    .WithConversationBridge(opt => opt.DefaultTenantId = "...") // conversation.{tenant}.*.state.changed
    .WithAgentBridge();                                         // agent.{tenant}.*.state.changed
```

Verificar que `IPushEventBus` publica a los 3 topics. Baseline behavior sin bridges permanece unchanged — bridges son aditivos.

**Acceptance:** integration test que conecta un SignalR client y observa los 3 topic patterns tras generar state changes sintéticos.

### C. `ILicenseGuard` runtime validation

- Confirmar que `Platform.Api` respeta `ILicenseGuard.CanExecute(feature)` donde los BackgroundServices Pro lo invocan (Dialer, EventStore, Analytics, AgentAssist, CallAnalytics)
- Verificar grace period 7d funciona según ADR-0006 (cache 10s + grace)
- Agregar test de integración que valida blocked scenarios (license expirada / revocada) emite métricas `asterisk.sdk.pro.licensing.guard` y retorna `503 Service Unavailable` donde aplica

### D. Resilience MVP — 3 critical external call-sites

Solo los 3 más críticos para v1.9.0. El resto se difiere a v1.9.1 (ver sección "Scope Explícitamente Diferido").

1. **`src/Asterisk.Platform.Api/Services/WebhookDeliveryService.cs`** — reemplazar custom `CircuitBreakerPolicy` + backoff array `[0, 60, 300, 1800, 7200, 18000, 28800, 28800]` por `ResiliencePolicy.ExecuteAsync("webhook.delivery", ct => ..., ct)`. Conservar backoff schedule como argumento configurable. Eliminar clase `CircuitBreakerPolicy` custom tras migración.
2. **`src/Asterisk.Platform.Mail/Services/SmtpSender.cs`** — reemplazar `for (var attempt = 1..2)` + `catch + Task.Delay(30s)` por `policy.ExecuteAsync("smtp.send", ...)`. 
3. **`src/Asterisk.Platform.Identity/OidcTokenExchange/OidcTokenExchangeService.cs`** — wrap `ExchangeCodeAsync` (PostAsync a token endpoint) con `policy.ExecuteAsync("oidc.token-exchange", ...)`. Retry en 502/503 + per-attempt timeout + circuit.

**Acceptance:**
- Meter `Asterisk.Sdk.Resilience` emite `retry_attempts{policy=webhook.delivery|smtp.send|oidc.token-exchange}` en `/metrics`
- Clase `CircuitBreakerPolicy` custom eliminada (verificable via grep)
- Tests de integración que provocan fallos transitorios y verifican retry + metric emission

### E. Sub-A critical fixes (carryover v1.5.0)

Bugs conocidos pendientes de v1.5.0, no relacionados a resilience pero bloqueantes para producción:

- **Bot handoff execution end-to-end** — handoff de bot a agente humano no completa el transfer
- **Hold/Unhold endpoints** — conversation endpoints en `Platform.Api` — comportamiento incorrecto
- **Outbound conversation creation** — creación outbound (tenant-aware) falla bajo ciertas condiciones

Archivos críticos: **tbd durante kickoff** — identificar vía `git log --grep` y issue tracker.

**Acceptance:** integration tests que reproducen cada bug original y verifican el fix.

### F. P0 security (Sub-C Tier 0 server-side)

**F.1 Impersonation privilege escalation:**
Archivos afectados:
- `src/Asterisk.Platform.Api/Endpoints/ManagementImpersonationEndpoints.cs`
- `src/Asterisk.Platform.Api/Services/JwtTokenService.cs`
- `src/Asterisk.Platform.Api/Middleware/TenantResolutionMiddleware.cs`
- `src/Asterisk.Platform.Storage.Postgres/Stores/PostgresAuditStore.cs`
- `src/Asterisk.Platform.Identity/AuthEvent.cs`
- `src/Asterisk.Platform.Audit/AuditEntry.cs`
- `src/Asterisk.Platform.Api/Serialization/ApiJsonContext.cs`

Accion: audit permission check antes de emitir tokens impersonados. Bloquear delegation hacia tenants con mayor privilegio que el caller. Asegurar que `AuditEntry` capture el impersonator + target + scope.

**F.2 MFA policy bypass backend:**
Archivos afectados:
- `src/Asterisk.Platform.Api/Services/MfaService.cs`
- `src/Asterisk.Platform.Api/Endpoints/AuthAdminEndpoints.cs`
- `src/Asterisk.Platform.Api/Endpoints/AuthEndpoints.cs`
- `src/Asterisk.Platform.Api/Endpoints/TenantSettingsEndpoints.cs`
- `src/Asterisk.Platform.Api/Services/TenantProvisioningService.cs`
- `src/Asterisk.Platform.Storage.Postgres/Stores/PostgresUserStore.cs`
- `src/Asterisk.Platform.Storage.Postgres/Stores/PostgresTenantAuthConfigStore.cs`
- `src/Asterisk.Platform.Identity/TenantAuthConfig.cs`
- `src/Asterisk.Platform.Identity/User.cs`

Accion: verificar enforcement de política MFA del tenant en **todos** los flows de auth: login, password reset, token refresh, admin operations, tenant provisioning. Agregar guard en `AuthEndpoints` que respete `TenantAuthConfig.MfaRequired`.

**Acceptance:**
- Tests que reproducen la explotación (pre-fix: retorna 200; post-fix: retorna 401 + audit entry)
- `FluentAssertions.Should().Be(401)` + `auditStore.Received(1).AppendAsync(...)` verified
- Manual pen-test checklist completed
