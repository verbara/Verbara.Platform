**Critical observations affecting risk register:**

1. **Risk R2 (JSONB) is partially mitigated by Canary A alone.** `PostgresSessionStore.cs:230-243` implements `private sealed class JsonbParameter(string json) : SqlMapper.ICustomQueryParameter` which calls `command.Parameters.Add(new NpgsqlParameter(name, NpgsqlDbType.Jsonb) { Value = _json })`. If Canary A passes the AOT runtime test, JSONB via `ICustomQueryParameter` interface is validated. PostgresAuditStore (Canary B) becomes complementary, not duplicative.

2. **New risk R9 — `DynamicParameters`**: `BuildSaveParameters` (line 104) builds `new DynamicParameters()` then `.Add("name", value, DbType.X)` × 9. This is Dapper's runtime-reflective parameter bag. **Dapper.AOT compatibility unverified for `DynamicParameters` shape.** If interceptor can't handle it → migration to anonymous types required (mechanical for Sessions.Postgres because the parameter set is fixed; non-trivial if any Pro package uses dynamic key sets).

3. **`{ get; init; }` row materialization NOT exercised** in Sessions.Postgres — all queries return `string?` JSON snapshots. **Risk R1 still requires Canary B** (`PostgresAuditStore`) for empirical validation.

4. **All call sites use `new CommandDefinition(...)`** rather than the simpler overload `conn.Execute(sql, param)`. Dapper.AOT must intercept this overload — common pattern, expected to work, but worth verifying.

5. **`InternalsVisibleTo` to test project**: `Verbara.Sdk.Sessions.Postgres.Tests` accesses internal types. Adding `Dapper.AOT` shouldn't affect this surface.
