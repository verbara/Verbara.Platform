## Issues found (must fix) — ALL FIXED INLINE THIS PASS

1. **Queue members route is wrong.** Doc said
   `POST /api/v1/admin/queues/{id}/members`. Actual route (R5.1
   RESTful-nesting refactor):
   `POST /api/v1/queues/{queueId}/members`. The `/admin/queue-members` legacy
   redirect exists for backward-compat but the per-queue nested form has no
   `/admin` prefix.
   **Fixed:** `first-deploy.md` Step 4 now uses `/api/v1/queues/$QUEUE_ID/members`.

2. **`ListQueues` returns a `PagedResult<QueueDto>`, not a flat array.** The
   `python3` parser walked `[q for q in json.load(...)]`, which would raise
   `TypeError` against `{items, totalCount, page, pageSize}`.
   **Fixed:** parser now reads `json.load(...)['items']`.

3. **`QueueDto.Id` (not `queueId`).** The destructured field name was wrong.
   **Fixed:** parser now reads `q['id']`.

4. **`CreateAgentRequest` does NOT accept `agentId` or `skills`.** The DTO is
   `(string UserId, string DisplayName, string? Extension, string? SipPassword)`.
   Posting `agentId` is silently dropped; posting `skills` is silently dropped.
   The downstream demo depends on the agent having the `sales` / `support`
   skill for routing.
   **Fixed:** Both `first-deploy.md` Step 3 and `first-realistic-demo.md` Step 2
   now (a) capture the server-assigned `id` from the create response, then (b)
   `PUT /admin/agents/{id}` with `{"skills": [...]}` to add the skill.

5. **AgentAssist runtime toggle endpoint URL is wrong.** Doc said
   `PUT /api/v1/admin/agentassist/feature`. Actual route:
   `PUT /api/v1/admin/features/agent-assist`. Permission required:
   `features:agent-assist:manage` (Platform Admin role grants it via the
   `platform_admin` template cloned in setup wizard).
   **Fixed:** `first-realistic-demo.md` Step 4 now uses the correct URL.

6. **AgentAssist re-enable body is incomplete.** Sending `{"enabled": true}`
   without `provider` + `credentials` fails validation (400). The doc shows
   exactly that 400-bound body.
   **Fixed:** the re-enable example now sends
   `{"enabled": true, "provider": "deepgram", "credentials": {"apiKey": "$DEEPGRAM_API_KEY"}}`.

7. **`POST /api/v1/admin/realtime/reconcile` does not exist.** The "Common
   pitfalls → Agent does not appear in queue" section pointed at a non-route.
   `RealtimeEndpoints.cs` only exposes `/admin/realtime/profiles/*`.
   **Fixed:** Pitfall now says wait 30s for the periodic reconciler, or
   restart the API container; flagged a first-class admin endpoint as R5.4
   backlog.

8. **`docs/dashboards/` link target is wrong.** From
   `docs/operations/first-realistic-demo.md`, `../dashboards/` resolves to
   `docs/dashboards/` which does not exist. The dashboards live at
   `docs/operations/dashboards/`.
   **Fixed:** link is now `dashboards/` (relative, resolves correctly).

9. **OpenAPI HTML URL is wrong.** Doc said `http://localhost:5000/docs`.
   The bundled API exposes Scalar at `/scalar/v1` and the raw spec at
   `/openapi/v1.json` (no `/docs` route is registered).
   **Fixed:** Step 8 now lists both correct URLs.

10. **`--scale platform-api=N` is not viable with the bundled compose.** The
    `platform-api` service pins `5000:5000`, so a scale-up triggers a host
    port collision. The cluster drain demo will fail at the scale-up step.
    **Fixed:** the cluster section now explains the constraint and points at
    `cluster-management.md` for the real recipe.

## Issues found (should fix)

- **`CreateUserRequest` ignores caller-supplied `userId`.** The DTO is
  `(string Email, string DisplayName, UserRole Role, string? Password)` —
  the platform mints the id. The doc passes `"userId": "acme-user-admin"`
  which is silently dropped. Not a hard break (the response contains the
  real id), but the seeded loops in `first-realistic-demo.md` Step 1 +
  Step 2 use `$UID` for predictability and the predictability is illusory.
  **Recommendation (not applied):** consume the response `id` everywhere a
  user id is referenced downstream. Skipped this pass to keep the diff
  surface-minimal; the docs still work because no later step depends on the
  `acme-user-admin` literal beyond `userId` of the agent create (which now
  uses `$UID` correctly because `CreateAgentRequest.UserId` IS the foreign
  reference, and the doc passes the same string both places).

- **Setup wizard description omits the auto-clone of `platform_admin` role
  template.** The docs imply day-1 the new admin has full powers. The code
  silently no-ops if the RBAC store is partial (`SetupEndpoints.cs` lines
  100-115). For most installs this works; degraded RBAC stores can produce
  a confusing 403 on `/admin/cluster`. Worth a one-line callout in a future
  pass.

- **`AGENT_ID` is set inside a `for` loop subshell in `first-realistic-demo.md`
  Step 2 only because the assignment is in the loop body, not a subshell —
  fine in bash. Verified the surrounding `for ext in 5001 5002; do` body
  inherits variables correctly. No fix needed.

## Issues found (nice-to-have)

- The `${t^}` parameter expansion (uppercase first letter) in
  `first-realistic-demo.md` Step 1 is bash-4-only. Linphone-running macOS
  users on default `/bin/sh` (zsh after Catalina) will get an error. A
  `bash docker-compose-...` shebang or explicit `bash -c` wrap could help.
- The "Save this Management API key in your password manager" callout in
  `getting-started.md` Step 4 could mention the alternative via UI:
  Platform Admin → API Keys → New (reveal-once UX shipped in R5.1).
- The `for i in $(seq 1 10)` traffic loop in
  `first-realistic-demo.md` Step 3 doesn't sleep enough — 10 calls × `sleep 12`
  = 2 minutes wallclock. Doc says "10 calls over 2 minutes" so this is
  consistent. However the originate fires & forgets, so the audio plays for
  the duration of `hello-world` (~2s) and most calls will overlap by ~10s
  of silence. Consider noting that the wallboard will show a sawtooth.
